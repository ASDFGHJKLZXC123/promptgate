## Required case-level provenance

Every committed dataset case must map to exactly one input provenance class:

- `observed-input`: exact retained symptom text; no paraphrase.
- `observed-validation`: exact retained invalid boundary input, if the final dataset intentionally exercises it.
- `policy-derived`: synthetic input derived directly from an immutable source rule; never called verbatim or observed.
- `fable-synthetic`: candidate generated by Claude Fable 5 / high and retained only after human review.

A case may additionally cite zero or more assertion-evidence references. `observed-output` identifies retained unsafe output used to justify an assertion; it is never the case's input provenance.

The final ledger must record for every case:

| Field | Requirement |
|---|---|
| Case ID | Stable dataset ID |
| Input provenance class | Exactly one input class from the list above |
| Parent evidence | Exact probe, source rule, or parent case ID |
| Assertion-evidence refs | Zero or more evidence IDs, including an `observed-output` probe where applicable |
| Expected label | Human-reviewed safety outcome |
| Assertions | Human-reviewed deterministic/rubric expectations |
| Review disposition | Accepted, edited, or rejected |
| Reviewer/date | Project owner and review date |
